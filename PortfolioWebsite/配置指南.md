# 作品集配置指南

## 1. 单一事实来源

公开页面主体只从 `content/pages/**/*.json` 读取。页面组件 type、props、顺序、slot 内容和 SEO 都应通过这条链路修改，不要在 `src/app/**/page.tsx` 中复制业务文案或图片配置。

其他配置来源：

- `content/font-lab/font-presets.json`：FontLab 字体预设。
- `content/component-design/component-design.json`：ComponentDesign 视觉参数。
- `src/components/playground/component-lab-registry.tsx`：ComponentLab descriptor 与演示入口。
- `PortfolioData.md`：历史参考，不是权威结构。

## 2. 页面文档契约

当前页面文档版本为 `1`，顶层只允许：

```json
{
  "version": 1,
  "root": {
    "props": {
      "title": "",
      "description": "",
      "image": "",
      "noIndex": false
    }
  },
  "content": [],
  "zones": {}
}
```

当前版本执行严格校验：

- 组件 type 必须存在于 Puck manifest。
- 每个组件只能包含其契约声明的 props。
- 每个组件必须有非空且全页唯一的 `props.id`。
- slot 递归校验子组件及允许类型。
- 链接拒绝 `javascript:`、`data:`、协议相对地址和控制字符。
- public 图片必须存在并精确匹配文件名大小写。
- `native` 图片预设不得配合 `cover` 或纵向裁切。
- 非法当前版本不能依靠默认值静默修复。

无版本旧文档只在显式迁移入口中转换；未来版本直接拒绝。编辑草稿可以补齐旧 id 和已知旧字段，但归一化后仍必须通过当前版本契约。

## 3. 本地编辑与发布

启动：

```bash
npm run dev:test
```

写操作需要：

```text
LOCAL_EDITOR_ACCESS_TOKEN=<本机随机值>
```

浏览器请求头为 `x-local-editor-token`。正常模式、生产模式、CI 或 Vercel 环境不允许本地文件写入。

Puck 页面发布固定经过：

1. slug 安全与规范化校验。
2. 编辑草稿宽松归一化或旧版本显式迁移。
3. `PageDocument` 当前版本严格校验。
4. 图片、媒体和链接校验。
5. 同 slug 写队列内原子替换 JSON。
6. 回读、重新解析并与写入文档比对。
7. 刷新页面 slug 列表。

契约失败返回 `422 INVALID_CONTENT`，响应保持：

```json
{
  "error": {
    "code": "INVALID_CONTENT",
    "message": "Page document failed strict validation",
    "issues": []
  }
}
```

## 4. 作品目录与下一项目

`content/pages/works.json` 中 `WorksList.entries` 同时定义作品顺序、canonical id、旧别名、封面和标题。`ContentRepository.readProjectCatalog()` 每次从同一次文档读取结果建立不可变投影，不存在永久模块单例。生产 Proxy 使用从该投影生成的纯别名表，不在请求阶段读取文件系统；`check:public-runtime` 会阻止别名表与权威目录不一致。

`NextProjectBlock` 的权威 JSON 只保存 `id` 与 `nextId`。公开渲染和编辑预览根据当前目录投影补充 `href`、名称和封面，不把派生字段写回内容文件。

新增或调整作品时必须同步确认：

- `/works/<id>.json` 存在。
- `works.json` 的 href、编号和别名唯一。
- 别名能够 308 重定向到 canonical URL。
- 最后一项的下一项目返回 `/works`。

## 5. 路由模式

公开路由位于 `src/app/(site)`，Route Group 不改变 URL。内部工具位于 `src/app/(tools)`。

- 关于页同时承载个人介绍与联系方式，站点不设置独立联系路由。
- `/sample-breakdown` 永远返回 404。
- 测试模式样本位于 `/playground/sample-breakdown`。
- 普通作品和灯光集合使用静态参数，未知合法 slug 返回 404。
- `/p/**` 旧地址保留重定向语义。
- 内容 JSON 损坏、schema 不兼容和 I/O 失败抛入错误边界，不返回 404。

## 6. FontLab 与 ComponentLab

FontLab 与 ComponentDesign 的当前版本保存接口采用严格校验。非法数值、错误枚举、缺失字段或未知字段不能再被默认值覆盖后写入。

字体相关调整只能进入 FontLab 预设链路；组件样本、默认文案、默认图片和默认参数只能进入 ComponentLab 配置链路。不要在业务页面 JSX 中长期硬编码这些数据。

本轮架构升级明确不做字体优化：不转换格式、不裁剪字符、不删除字重、不改变 preload、fallback、`localFont` 参数或实际视觉呈现。

## 7. 验证命令

```bash
npm run check:public-runtime
npm run check
npm run build
npm run report:build
```

`dev`、`dev:test` 和 `build` 会自动生成按路由拆分的公开 Puck 运行时与作品别名表；修改组件 manifest 或 `works.json` 别名后可手动执行 `npm run generate:public-runtime`。`dev:test` 对新加入当前路由清单的合法组件使用完整公开 renderer，生产仍保持按路由裁剪。生产 `build` 固定使用 Next 16 的 Webpack 路径，Turbopack 兼容性恢复另行处理。`check:public-runtime` 只验证生成结果是否过期，不修改文件。`report:build` 只读取 `build-manifest.json`、`server/app-paths-manifest.json`、预渲染/Proxy 清单和由路由键精确派生的 Client Reference Manifest，将公开路由类型、客户端组件和首载资源写入 schema v2 的 `.next/build-report.json`，同时验证 Proxy 跟踪清单不含 `content/` 或 `public/`。

`npm run migrate:content` 只用于将受支持的旧页面文档显式迁移到当前 `PageDocument` 版本。脚本先预检整个批次，再只原子写入旧文档；当前版本保持字节不变，校验失败时不得用迁移脚本掩盖数据错误。

涉及 slug、上传、API、Puck、FontLab、ComponentDesign 或图片路径时必须补正常和异常测试。涉及页面布局或视觉系统时，还要更新 Playground、相关规范并执行桌面、平板和移动视口回归。
