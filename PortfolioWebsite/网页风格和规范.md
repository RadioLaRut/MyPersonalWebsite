# 网页风格与设计规范

本文档记录当前 `PortfolioWebsite` 的真实站点实现，用于约束后续页面扩展、Puck 内容搭建、组件排版和视觉调整。本文档描述的是当前线上风格快照，不负责定义尚未落地的未来目标。

## 1. 文档定位

- 以当前源码、当前内容 JSON 和当前页面可见效果为准。
- 页面组织以 Puck 内容页为核心，而不是单独手写模板优先。
- 新增页面、区块或组件时，优先复用现有组件与 token，不重新发明平行风格。
- 新增组件必须同步更新到 `/playground`，确保样式与排版可回看、可比对。
- 任何组件或页面的排版调整都必须遵循统一网格，不允许脱离栅格做自由摆放。

## 2. 站点当前结构

当前公开页面以以下结构为主：

- 首页 `/`：`HeroSection -> ProjectCoverLink -> ProjectCoverLink -> ProjectCoverLink -> HomeEndcapSection`
- 关于页 `/about`：`EditorialHeader -> ThreeColumnSection -> ContactFlashlight -> HomeEndcapSection`
- 作品归档 `/works`：`WorksList -> HomeEndcapSection`
- 灯光归档 `/works/lighting-portfolio`：`EditorialHeader -> ProjectCoverLink -> NextProjectBlock`
- 作品详情 `/works/[id]`：由 `HeroHeadline`、`BilibiliEmbed`、`RichParagraph`、`ThreeColumnSection`、`EditorialSplit`、`ImageSlider`、`ParameterGrid`、`ImagePanel`、`NextProjectBlock` 等区块按 JSON 组合
- 灯光集合详情 `/works/lighting-portfolio/[id]`：同样由 Puck JSON 驱动渲染

当前网站不是“首页、作品页、联系页完全独立设计语言”，而是在统一视觉系统下，通过不同内容块组合出不同页面密度与节奏。

## 3. 全局视觉基础

### 3.1 背景与色彩

- 页面基础背景为深黑色，核心变量来自 `:root`：
  - `--background: #050505`
  - `--foreground: rgba(255, 255, 255, 0.9)`
  - `--surface-elevated: rgba(255, 255, 255, 0.05)`
  - `--surface-muted: rgba(255, 255, 255, 0.03)`
  - `--border-subtle: rgba(255, 255, 255, 0.1)`
- `html` 与 `body::before` 叠加顶部与边缘的径向光晕、纵向渐变，不使用纯平黑底。
- Tailwind 扩展色以当前 token 为准：
  - `textPrimary: rgba(255, 255, 255, 0.75)`
  - `textSecondary: rgba(255, 255, 255, 0.62)`
  - `textMuted: rgba(255, 255, 255, 0.50)`
- 白色只用于最高层级标题、交互高亮和关键边线。连续正文和说明文本默认使用 `textSecondary`，`textMuted` 只用于编号、标签和元信息。
- 分隔线默认使用 `border-white/10` 到 `border-white/20`，避免硬边。

### 3.2 表面质感

- 卡片、浮层和灯光归档封面优先使用轻量玻璃质感，而不是重投影卡片。
- `glass-panel` 是当前半透明面板标准：
  - 线性渐变背景
  - 细白边
  - `backdrop-filter: blur(24px)`
- 文字高亮更多依靠反差、混合模式和透明度，不依赖大面积发光。

## 4. 栅格与对齐

### 4.1 核心栅格

- 全站统一使用 12 列 `.grid-container`。
- 当前实现不是旧版“移动端 4 列，平板以上 12 列”，而是所有设备统一 12 列。
- `.grid-container` 规则如下：
  - `grid-template-columns: repeat(12, minmax(0, 1fr))`
  - 默认 `gap: 1rem`
  - `1024px+` 时 `gap: 1.5rem`
  - 容器宽度为 `width: min(92vw, 1680px)`，容器自身不再叠加水平 padding
  - 对应两侧安全边距为 `4vw`
  - 测试模式下的网格辅助线必须按“列宽”和 `gap` 分离绘制，每列显示左右边界，不得把 `gap` 误读成列宽的一部分

### 4.2 常用对齐辅助类

- `grid-content`：标准内容区，`col-start-2 col-span-10`
- `grid-narrow`：窄内容区，`col-start-3 col-span-8`
- `grid-full`：全宽内容区，`col-start-1 col-span-12`
- `grid-left`：左侧内容区，`col-start-2 col-span-5`
- `grid-right`：右侧内容区，`col-start-7 col-span-5`
- `grid-sidebar`：右侧信息栏，`col-start-9 col-span-4`
- `grid-offset-center`、`grid-offset-right`：用于三联图或错位信息块
- `.grid-subgrid`：组件内部继续使用 12 列与全局 `gap`，用于 Header 等嵌套网格，禁止额外叠加会造成移动端溢出的固定大间距

### 4.3 纵向节奏系统

- 当前站点采用“12 列纵向栅格 + 纵向节奏系统”的双轨规则，不采用严格逐行 baseline grid。
- `8px` 是最小节奏单位，处理按钮内边距、标签间距、局部文字组之间的微调。
- `32px` 是主节奏单位，处理区块级 `pt/pb/mt/mb`、分隔线后的进入留白、页面收束和模块交接。
- 区块外轮廓必须回到 `32px` 节奏线上；组件内部优先使用 `16 / 24 / 32 / 48` 这类 `8px` 倍数做微调，仅在标签锁定、次级说明等光学修正场景下允许使用 `4px`。
- 当前全局节奏 token 与工具类如下：
  - `rhythm-section-compact`：手机端 `48px / 48px`，桌面端 `64px / 64px`
  - `rhythm-section-normal`：手机端 `64px / 64px`，平板端 `80px / 80px`，桌面端 `96px / 96px`
  - `rhythm-section-spacious`：手机端 `80px / 80px`，平板端 `96px / 96px`，桌面端 `128px / 128px`
  - `rhythm-section-hero`：手机端 `96px / 64px`，平板端 `128px / 96px`，桌面端 `160px / 128px`
  - `rhythm-block`：跟随 spacious 档，手机端不再继承桌面的 `128px` 黑场
  - `rhythm-block-compact`：跟随 normal 档，手机端为 `64px`
  - `rhythm-divider-top`：跟随 compact 档，手机端为 `48px`
  - `rhythm-stack-2 / 3 / 4 / 6 / 8`：内部垂直堆叠工具类，对应 `16 / 24 / 32 / 48 / 64px`
- `HeroSection`、页头 Header、`WorksList`、`HomeEndcapSection`、`StatementBlock` 等 section 级组件应优先通过这些 profile 控制纵向节奏，不再直接散写大块 `pt-*`、`pb-*`。
- 全屏图像段落、转场段和特殊叙事段允许破格，但必须在组件语义上明确自己是例外，不允许匿名脱离主节奏。

### 4.4 对齐规则

- 不允许把整页内容简单垂直堆叠后整体居中。
- 标题、正文、补充信息、CTA 必须通过跨列与偏移建立层次。
- 正文、描述和图注类长文本统一通过 `Typography.align` 选择 `left / center / right / justify`。`justify` 必须同时输出 `text-align: justify` 与 `text-align-last: justify`，确保段落末行及强制换行前的最后一行也贴齐两端。
- `justify` 状态不得应用 Typography 的左右光学位移，文字盒本身必须同时贴齐左右边界。对齐值属于 ComponentLab 的共享节点版式，不进入 Puck 页面实例或 FontLab 字体预设。
- 页面标题、区块标题、按钮、CTA、导航、编号、眉题、分类、短标签和图片滑杆标签不开放两端对齐，避免单行文字被强制拉伸。
- `StatementBlock` 继续只提供左、居中、右三种对齐；它的职责是通过可控的大留白形成叙事换气，不并入普通正文组件。
- 同一视觉行内使用不同字体预设或字号的文字必须按共同基线对齐，不得通过局部 `padding` 或负 `margin` 模拟对齐；下划线、锁线和状态短线等装饰元素必须脱离文档流，不能改变文字盒的对齐尺寸。
- 大图内容和文本内容必须共享同一套栅格边界，不能出现图像自由出血、文本另起一套参考线的情况，除非该组件明确就是全屏图像段落。
- 新增区块优先复用已有栅格辅助类，避免在组件里写新的随意 `col-start` 组合。

## 5. 排版系统

### 5.1 字体预设

当前站点排版不再按“Display / Serif / Mono”三段粗略区分，而是通过 `Typography` 组件统一调用以下 4 套预设：

- `sans-body`
  - 拉丁字族：Futura
  - 中文字族：汉仪旗黑
  - 用途：正文、说明、标签、按钮、元信息
- `luna-editorial`
  - 拉丁字族：Luna
  - 中文字族：思源宋体
  - 用途：大型标题、首页主视觉、作品标题、页尾收束标题
- `gothic-editorial`
  - 拉丁字族：ITC Serif Gothic
  - 中文字族：思源宋体
  - 用途：分类、短标签、带编辑感的辅助标题
- `classical-display`
  - 拉丁字族：DM Serif Display
  - 中文字族：思源宋体
  - 用途：导航抽屉菜单的大号菜单字

### 5.2 字号层级

当前字号 token 以 `Typography` 系统为准：

- `caption`：极小型标签、编号说明、索引辅助信息
- `label`：按钮、分类、菜单说明、短标签
- `body-sm`、`body`、`body-lg`：正文与介绍文案
- `title-sm`：区块标题或密集信息块内标题
- `title`：作品列表标题、次级大标题
- `display`：页头主标题
- `hero`：最大级别标题
- `menu`：导航抽屉菜单字

标题层级采用统一的原版基准行高：`title-sm = 1.05`、`title = 0.92`、`display = 0.88`、`hero = 0.90`、`menu = 1.00`。所有包含这些档位的 FontLab 预设必须保持一致；组件不得再用局部 `leading-*`、负 margin 或额外字号补偿改写标题文字盒。

### 5.3 字重与混排

- 字重由预设内部映射控制，不能简单理解成同一套字体粗细。
- 当前系统会按 script 自动拆分拉丁文和中文，再分别应用对应字族、字重、基线偏移和字距。
- 这套机制是当前站点中西文混排一致性的核心，新增文本组件应继续走 `Typography`，不要回退到裸 `h1`、`p` 加 Tailwind 类名的做法。

### 5.4 换行策略

- `wrapPolicy="heading"`：标题类文本，允许平衡换行
- `wrapPolicy="prose"`：正文类文本，强调阅读舒适度
- `wrapPolicy="label"`：标签类文本，默认大写且尽量不换行
- `wrapPolicy="url"`：邮箱、微信等可复制长文本
- `wrapPolicy="code"`：仅用于需要保留换行和长文本断开的场景
- 中文连续正文在桌面端收窄到约 32—42 字一行；`RichParagraph` 默认使用包含末行的两端对齐，不以局部行高、字距或字号覆盖换取行宽。

### 5.5 FontLab 与 Typography 硬约束

- 任何字体相关调整都不得绕过 FontLab 与 Typography 既有链路。禁止在组件内直接硬编码 `fontSize`、`lineHeight`、`letterSpacing`，禁止局部覆盖 Typography token，禁止添加 fallback 尺寸来伪造目标效果。
- `RichParagraph`、`EditorialSplit` 及其他走组件设计配置链路的文本组件，必须继续使用其既有可配置字号 token。若需把正文从 `body-lg` 调整为 `body` 或其他档位，只能修改对应配置源，如组件设计文档、配置 schema 或持久化配置；严禁直接在组件内部把 `size` 硬编码成某个字号。
- 遇到字号闪动、首屏与 hydration 不一致、刷新后样式回退、字重异常、行高异常等问题，必须优先修复 FontLab 变量注入、配置读取、Typography token 映射或相关链路本身，不得使用局部回退样式或硬编码掩盖根因。
- 严禁因单个页面、单段文字或局部视觉需求，直接修改 `PortfolioWebsite/content/font-lab/font-presets.json` 中的 Futura+汉仪旗黑、Luna、Gothic 预设字号配置。
- 任何“把某段文字变大 / 变小 / 更紧 / 更松”的需求，默认只能通过切换该文字使用的字号档位、组件层级或既有配置链路来解决，不得借机改动 FontLab 的字号、字重、行高或字距配置。
- 只有当用户明确提供新的全局 FontLab 配置表，并明确要求同步到 `PortfolioWebsite/content/font-lab/font-presets.json` 时，才允许修改这些预设；除此之外必须保持不动。

### 5.6 公开字体交付

- 字体子集属于传输优化，不属于视觉设计调整。公开站与工具页必须消费同一套 FontLab 变量和 Typography 语义，不得因文件变小而改变字族、字重、行高、字距、混排拆分或换行宽度。
- 公开站统一使用一个全站字符集，不按页面切割。字符自动来自页面 JSON、公开固定文案、metadata、FontLab 与 ComponentLab 预设；文本保存后由开发监听器更新，禁止维护第二份手工字符名单。
- 只有 `content/fonts/font-licenses.json` 中具备明确网页嵌入与子集授权证据的字体可以生成 WOFF2 子集。证据不足的字体必须保留原文件并按需加载，不得擅自转换或替换外观。
- Admin、Puck 预览、FontLab 与 ComponentLab 使用完整字体。公开页不得预加载完整字体；每条公开路由的字体预加载最多 4 个，实际清单由 `PublicFontHint` 投影。
- 原始字体不得删除或覆盖。生成的公开 WOFF2、字符集和 manifest 是可复现的派生产物，必须作为普通 Git 文件提交。

## 6. 图片与媒体呈现

### 6.1 图片预设

当前站点的图片尺寸规范统一走 `PresetImage` 和以下预设：

- `ratio-16-9`
- `ratio-21-9`
- `native`

对应的适配模式为：

- `x`：横向优先
- `y`：纵向优先
- `cover`：填满容器

### 6.2 使用原则

- 所有用户可见图片必须保持直角边界，不允许在站点前台对图片容器或图片画面使用任何 `rounded-*` 圆角样式。
- 首页 Hero、详情 Hero、灯光封面、作品列表预览图都依赖图像和深色遮罩叠加来建立氛围。
- 大图上方通常会再覆盖一层或多层黑色渐变，以保证白色标题可读。
- 默认不允许浏览器原生拖拽媒体元素；正式模式下图片、视频、SVG、Canvas 都关闭默认拖拽与选择。
- 新增图片区块必须明确设定预设比例和 fit mode，不能把图片当作无约束内容直接塞入布局。
- `PresetImage` 可通过 `fitModeByBreakpoint` 与 `objectPositionByBreakpoint` 分别定义 `base / md / lg` 画面策略；平面 `fitMode` 仍作为兼容回退。
- 所有走 `PresetImage` 的固定画框图片在资源尚未就绪时显示统一的细线扫描加载态；加载完成后淡出，加载失败时停止循环动画。
- `native` 只允许与 `x` 组合；`native + y` 和 `native + cover` 属于无效配置，必须改用固定画框比例承载裁切或纵向适配。
- 所有可选媒体遵循“未填写就没有”：不得保留空媒体列、空图片节点或占位框。`ProjectCoverLink` 未填写封面时退化为纯色文字入口，`EditorialSplit` 未填写图片时退化为纯文本结构，`ThreeColumnSection` 每栏独立决定是否出现图片。
- 新增图片组件必须选择与 12 列占宽一致的 `MediaLayoutProfile`，由该 profile 生成 `sizes`。只有真正横跨视口的媒体允许声明 `100vw`，不得用统一默认值让浏览器下载过大图片。
- 每条公开路由最多允许一个 `PublicMediaHint.preload`。首个有效首屏媒体由页面 JSON 自动投影，其余图片在初始 HTML 中保持懒加载，组件默认值不得自行批量抢占首屏带宽。
- 公开页首次直达或刷新时显示统一黑场开场，只等待首张明确高优先级或位于首屏内的图片，且必须设置最大等待时间；首图结束或超时后立即开放页面，不得阻塞到整页图片全部完成。
- 开场完成后，页面级图片协调器以低优先级和受控并发预热当前页其余已声明图片；站内路由切换不重复完整开场，但必须重新执行当前页图片预热。需要交互后才显现的图片仍应在初始 DOM 中声明为懒加载资源，确保预热器可以发现，同时不得因此提前显示。

### 6.3 B 站视频

- 站内唯一视频组件为 `BilibiliEmbed`，使用 B 站官方 `player.bilibili.com` iframe；不提供本地视频播放器，也不在 `ParameterGrid` 中保留自动播放、循环播放或 `isVideo` 分支。
- `source` 只接受 BV 号或 `bilibili.com/video/BV…` 标准视频链接，并只解析安全整数形式的 `p` 与 `t`。短链、直播、番剧、播放器 URL、iframe 代码、脚本协议和非 B 站域名一律拒绝。
- 播放器固定为 `16:9`，默认展示封面、关闭自动播放、关闭弹幕，使用懒加载，并在下方始终提供“在哔哩哔哩观看”外链。
- 空值或非法值在公开页面不渲染；Admin 与 ComponentLab 显示纯色错误状态。总览 HTML 只画纯色结构示意，不实际请求 B 站。
- 站点 CSP 的 `frame-src` 只允许 `'self'` 与 `https://player.bilibili.com`，不得用 `frame-ancestors` 代替 iframe 来源控制。

## 7. 页面级风格规范

### 7.1 首页

- 首页是“沉浸式入口 + 三段重点项目 + 收束 CTA”，不是传统简历式首页。
- `HeroSection` 采用真正的 full-bleed 全屏大图与海报式单栏文字锁定，并使用 `rhythm-section-hero` 控制首屏落版位置；桌面端文案默认锁在右侧暗部的窄文案柱，而不是压在主体人物上或拆成独立说明区。
  - Hero 图片默认只做水平对齐，不做 Y 轴 cover；上下黑边允许存在，但不能牺牲主体构图或把文字压到人物主体上。
  - 当首页 Hero 不承载说明段和 CTA 时，默认启用极简海报模式：主视觉标题 + 底部身份信息，不显示副标题；仅在明确提供副标题时才启用覆盖式副标题结构。
  - 极简模式下主标题使用正常对比度，不以淡底字处理。
  - 极简模式下身份信息与主标题应保持紧锁，不应被拉出过大的断层。
  - 首页主标题使用 `luna-editorial`，副标题短标签与底部身份信息统一使用 `sans-body`。
- Hero 背景存在轻微视差和缩放，不做夸张运动。
- 移动端 Hero 与项目段使用 `100svh`，图片改为 `cover` 并从内容配置读取移动端焦点；桌面端继续保留原有水平对齐策略。首页姓名锁组在移动端落在画面底部右侧，避免覆盖主体面部。
- `ProjectCoverLink` 的 `immersive` 变体使用整屏或接近整屏的项目段落，标题压在图像之上，通过左右交替形成节奏，文字落版应回到 `rhythm-section-normal`。
  - 移动端的全屏媒体层必须解除 16:9 / 21:9 画框锁定，以 `cover` 和内容焦点填满整个 section；不能把桌面横图等比缩进 `100svh` 后留下上下黑带。
  - 移动端媒体层必须为视差位移预留纵向 overscan，且段落交界只保留浅层顶部渐变，不使用桌面端的全黑收口；相邻项目之间不能因位移露底或渐变形成看似额外 section 的纯黑横带。
  - 项目标题默认使用 FontLab 的 `luna-editorial / display` 档，最高级 `hero` 档只留给真正的页面主视觉。
  - 项目标题下方的锁线宽度应跟随标题可见宽度，而不是使用固定百分比。
  - 项目标题上方的辅助小字统一使用 `sans-body`，不使用 editorial serif preset。
  - 项目标题上方辅助小字到标题、以及标题到锁线，应使用同一锁组间距控制。
  - 当标题字体盒子导致底线视觉上偏远时，应通过底线光学校正上提，而不是继续堆负 margin。
  - 当前项目标题锁组以 `12px` 为基础间距；光学校正只作用于标题到锁线，不得同时吞掉辅助小字到标题的间距。
  - 紧行高标题默认不上提底线；包含 CJK 字形的标题在 `12px` 基础间距之外增加 `12px` 字体下沿度量补偿，纯拉丁标题不应用该补偿。锁线必须绝对定位并退出文档流，避免与越出行盒的字形相撞或改变锁组对齐尺寸。
- 首页收束区 `HomeEndcapSection` 使用中心式收束，但仍服从栅格，不是任意居中漂浮；该区块默认属于 `rhythm-section-spacious`。
  - 居中收束标题统一使用 FontLab 的 `luna-editorial / display` 档，不得占用页面主视觉使用的 `hero` 档。
  - 标题、说明文字与 CTA 必须共享同一条中心线；说明文字使用受控最大宽度并在内容列内居中。
  - HTTP(S) 外部 CTA 在新标签页打开并带安全的 `rel`；站内 CTA 与页内锚点保留当前页导航。

### 7.2 关于页

- 当前联系信息已经并入 `/about`，因此关于页同时承担自述、方法论和联系页职责。
- 页首 `EditorialHeader` 的 `index` 变体延续站点统一的大标题页头语言，不另起一套风格；页头 section 默认属于 `rhythm-section-hero`。
- `RichParagraph` 用于较长段落的个人叙述，内容宽度收窄，强调阅读节奏。
- `ThreeColumnSection` 的 `phase` 或 `evidence` 变体用三列密度递进的方式组织背景、方法和结果，而不是单列长文。
- `ContactFlashlight` 是关于页最强交互特征：深浅两层文字叠加，通过鼠标遮罩揭示亮层文本；外层 section 仍需回到主节奏线。
- 联系区使用 `contact` 锚点；邮箱必须提供 `mailto:` 链接，微信号必须提供复制按钮及读屏可感知的成功、失败反馈。
- 联系方式使用 `copyable-contact`，即使在正式模式下也允许选择和复制。

### 7.3 全部作品页

- 当前 `/works` 是档案式索引，不是卡片瀑布流。
- `WorksList` 使用横向分隔线切出每个条目，标题、编号、分类与描述分层明显；列表外层默认属于 `rhythm-section-normal`。
- `WorksList` 标题使用“作品索引”，并显示 `01—09 / 精选项目` 的索引说明。
- `WorksList` 标题区到分隔线、分隔线到首条作品各保留 `32px`，不得再叠加成连续的大块黑场。
- `WorksListEntry` 的默认标题使用透明填充与 `1px` 描边，分类始终可见；激活后标题恢复白色实心，并显示图像预览与完整描述。
- 序号与标题按共同文字基线对齐；序号下方的激活短线使用绝对定位，不得参与序号列的布局高度。
- 手机端 `WorksListEntry` 使用“编号窄列 + 标题与说明主列”的紧凑档案构图，标题使用 `title` 层级，激活图像以 `cover` 填满条目；条目最低高度从窄屏的 `26svh` 逐级过渡，内容增多时允许自然撑高，避免固定大画框制造无意义黑区，也不得以压缩行高换取密度；不直接把桌面三栏堆成单列，也不保留横图上下黑带。
- 激活态描述应优先写成“冲突 / 机制 / 阅读价值”式一句话，并带有明确进入提示，不能只写泛化标签或岗位名。
- 桌面端通过 hover 或键盘焦点激活条目；移动端通过视口中心感应区自动展开当前条目。
- 列表页的图像只在激活时显现，不做永久缩略图平铺。

### 7.4 灯光归档页

- `ImageSlider` 必须显示可见标题，明确告诉用户当前在比较什么；底部左右标签必须贴齐图片左右边界，不允许右侧标签停在中线附近。
- `ImageSlider` 必须具备真实 `slider` 语义，支持方向键、Home、End、Page Up、Page Down，并通过 ARIA 暴露当前比例与左右状态。
- `EditorialHeader` 的 `collection` 变体用于灯光归档首页标题，语气更像 curated index，而不是项目详情头图，页头节奏与其他 Header 保持一致。
- 灯光归档首页的侧栏说明不应为空；至少需要交代归档维度，例如镜头、情绪、时间变化或空间层次。
- `ProjectCoverLink` 的 `card` 变体是当前灯光归档的核心呈现方式：
  - 外层使用 `glass-panel`
  - 封面图占主导
  - 顶部显示集合编号与进入提示
  - 卡面底部标题必须存在，避免用户只能依赖封面猜测集合内容
  - 手机画框为 `16:9`，`768px+` 为 `21:9`，统一使用 `cover`
  - 手机端相邻集合卡片之间保留 `32px` 总间隔，避免沿用桌面的 `64px` 黑场
  - 允许轻微 hover 缩放，不使用复杂翻转或多层卡片动效

### 7.5 作品详情页

- 详情页不是统一模板复刻，而是围绕项目内容使用多个拆解型区块组合。
- `EditorialSplit` 的堆叠变体以分隔线组织标题和正文；标题到线、线到正文各保留 `24px`，不能把同一个 `48px` token 在两侧重复使用。
- 当前常见区块组合包括：
  - `HeroHeadline`
  - `BilibiliEmbed`
  - `RichParagraph`
  - `ThreeColumnSection`
  - `BreakdownHeadline`
  - `EditorialSplit`
  - `ImageSlider`
  - `ParameterGrid`
  - `ImagePanel`
  - `NextProjectBlock`
- 详情页的视觉目标是“项目拆解文档”，强调阶段、结构、证据和结果，而不是单纯展示一串美术图。

## 8. 交互与动效规范

### 8.1 滚动

- 全站使用 Lenis 做平滑滚动。
- 平滑滚动是默认体验的一部分，但不能影响可访问性或页面焦点管理。
- 路由变化时不得强制回到页顶；浏览器 Back 应恢复作品索引原位置，带 hash 的联系链接应正常定位。

### 8.2 自定义光标

- 只有 `CustomCursor` 已实际挂载、设备支持高精度指针且用户未开启减少动态效果时，根节点才设置 `data-custom-cursor-active="true"`；全局 CSS 只能以该属性作为隐藏系统光标的依据。
- 光标基础形态为白色圆点，使用 `mix-blend-mode: difference`。
- 悬停文本和交互元素时会扩大；磁吸状态会产生更强的聚焦反馈。
- `CustomCursor` 卸载或输入条件变化时必须清理激活属性，禁止用路由白名单或页面临时属性补偿清理失败。
- 工具布局不挂载 `CustomCursor`，因此 `/playground`、FontLab、ComponentLab 与 `/admin` 始终使用系统光标。

### 8.3 导航

- 当前站点导航为固定在右上角的 `MENU` 按钮，不是传统顶部横向导航栏。
- 打开后为右侧抽屉式菜单，带模糊遮罩和大字号菜单文字。
- 菜单项使用 `classical-display`，当前活动项有细竖线指示。
- 导航按父级路由识别活动项并提供 `aria-current`；必须保持键盘焦点圈定、可见焦点轮廓和 `Escape` 关闭能力，抽屉离场时立即进入 `inert` 状态。

### 8.4 页面动效

- 首页 Hero 与项目段落由公开页轻量运动协调器统一驱动，作品列表预览和关于页探照灯由各自最小交互层驱动；菜单抽屉等独立交互仍可按需加载 Framer Motion，但整体方向仍然克制。
- 当前站点的动效原则是“慢、轻、可感知”，而不是频繁弹跳或过度加速。
- 公开站开场属于全站唯一的页面载入编排：沿用 `#050505` 黑场、Typography 字体预设与细线扫描语言，不显示无法对应真实网络进度的百分比；首图就绪后先完成细线，再一次性揭示页面。减少动态效果时取消扫描与遮罩位移，只保留资源等待和即时切换。
- 动效主要承担以下任务：
  - 建立图像与文字的前后景关系
  - 强化滚动中的节奏切换
  - 提供 hover 或焦点反馈
  - 放大当前阅读位置
- `StatementBlock` 这类转场区块除了控制视觉高度，还应声明自己属于 `small / medium / large` 哪一档节奏型区块。

### 8.5 站点模式

- `data-site-mode="normal"` 是当前正式展示模式：
  - 全局禁止文字选择
  - 媒体元素禁止默认拖拽
  - 保持更强的画廊式沉浸感
- `data-site-mode="testing"` 是当前内部测试模式：
  - 允许文本选择
  - 选中效果为高反差白底黑字
  - 默认显示极淡的竖向调试网格细线，固定在页面文档坐标中，用于排查列对齐与安全边距问题
  - 便于校对文案、复制内容和进入内部工具
- `copyable-contact` 属于正式模式下的例外能力，只用于邮箱、微信等需要被复制的联系信息。

### 8.6 统一交互系统

- 新增或修改动效、hover、focus、pointer、drag、视口感应和链接语义时，必须优先接入 `src/lib/motion` 与 `src/components/motion`，不得在业务组件里重新散写一套输入判断或动画参数。
- `src/lib/motion` 负责交互基础能力：`tokens` 管理时长、缓动与 stagger；`variants` 管理常用进入、淡入、菜单和图像稳定动效；`input` 管理 fine/coarse pointer、hover 与 reduced-motion 判断；`drag` 管理滑杆百分比、拖拽边界和横纵手势意图；`scroll` 管理视口中心感应。
- `src/components/motion` 负责公共交互组件：整块可点入口使用 `MotionLink`，按钮使用 `MotionButton`，视口进入动效使用 `Reveal`。如果组件需要真实链接语义，不得用 `div` 加 `window.location` 伪装跳转。
- 首页 `ProjectCoverLink`、作品列表 `WorksListEntry`、灯光集合卡片、下一项目入口和内部工具入口都应保持真实链接或按钮语义，支持键盘聚焦、新标签打开、长按链接和 Next 预取。
- 移动端拖拽必须先判断横纵方向：横向明确后才接管交互，纵向明确时必须释放给页面滚动。`ImageSlider` 只负责同一镜头的无光照与有光照对比，不把 Day/Night/Fog 等叙事状态改成滑杆端点。
- 自定义光标、ContactFlashlight、WorksListEntry 这类输入能力分支必须复用统一输入能力判断；不得在组件内部用各自不同的 `matchMedia` 规则长期分叉。

## 9. 内容搭建规范

### 9.1 内容来源

- 页面内容以 `content/pages/**/*.json` 为单一内容源。
- 路由通过 `renderPuckPage` 渲染 JSON，不直接在页面文件里硬编码内容主体。
- 首页、关于页、作品归档、灯光归档和详情页都遵循这套内容驱动方式。

### 9.2 新增内容块的要求

- 所有图片类内容块都必须遵循直角图片规则；如果区块含有对比滑块，还必须提供可见标题和左右边界对齐的标签。
- 优先在现有 Puck 组件类别中扩展：
  - 基础布局
  - 作品展示
  - 关于与联系
- 新增区块必须说明自己属于哪类页面节奏，不允许出现语义不明的“万能区块”。
- 所有文本必须优先接入 `Typography` 系统。
- 所有图片必须优先接入 `PresetImage` 体系。
- 新区块的默认排版必须直接落在统一 12 列网格上。

当前作者侧固定提供 17 个组件：

1. `HeroSection`
2. `HeroHeadline`
3. `EditorialHeader`
4. `EditorialSplit`
5. `ThreeColumnSection`
6. `StatementBlock`
7. `RichParagraph`
8. `ImagePanel`
9. `BilibiliEmbed`
10. `ProjectCoverLink`
11. `WorksList`
12. `ParameterGrid`
13. `ImageSlider`
14. `BreakdownHeadline`
15. `NextProjectBlock`
16. `HomeEndcapSection`
17. `ContactFlashlight`

合并后的结构枚举固定为：

- `EditorialHeader.variant`：`index / collection`
- `EditorialSplit.layout`：`media-left / media-right / stack`；`bodyMode`：`plain / slot`
- `ThreeColumnSection.variant`：`triptych / phase / evidence`；`rhythm`：`aligned / staggered`
- `ProjectCoverLink.variant`：`immersive / card`

`WorksListEntry`、`MetadataListItem`、`TextParagraphBlock` 仅作为内部 Slot 类型存在，不显示在顶层添加菜单。旧的 `PortfolioHeroHeader`、`LightingCollectionHeader`、`ContentCard`、`TextSplitLayout`、`HighDensityInfoBlock`、`BreakdownTriptych`、`ProjectSection`、`LightingProjectCard` 只保留为迁移来源或底层视觉实现，不再成为作者可选组件。

### 9.3 页面编排原则

- 首页负责筛选和导向，不承担完整简历功能。
- 关于页负责方法、身份与联系信息整合。
- `/works` 负责索引，不承担完整项目叙事。
- `/works` 中 01—09 的条目顺序、名称、封面、URL 与 legacy alias 是项目目录的唯一来源；`NextProjectBlock` 内容模型只保存 `nextId`，其余信息从目录解析。
- 详情页负责拆解与证明，应使用多段结构而不是单段长文。
- 灯光归档页优先展示系列氛围与集合入口，不提前展开完整分析。

### 9.4 Puck 单向渲染链

- 页面 JSON 只提供内容与组件树，`content/component-design/component-design.json` 只提供共享版式设计，唯一组件渲染适配器负责把二者组合为最终节点。
- 组件类型、分类、renderer key、属性结构 key、实验室可见性和媒体布局由 `PuckComponentDescriptor` 统一记录并派生消费端清单；复杂字段函数仍保留在独立 schema，不得塞入可序列化描述符。
- 公开页、Admin 与 ComponentLab 必须引用同一组 canonical renderer；Admin 配置只维护字段、默认值和分类，不得再实现第二套 JSX。
- `RenderSurface` 仅允许区分 `public`、`editor`、`lab` 的交互状态。`editor` 与 `lab` 可以关闭跳转、拖拽和动画，但不得改变尺寸、字体语义、文本结构、栅格位置或图片裁切。
- 标题、副标题、眉题、正文、描述、图片说明和按钮文案允许在 Admin 画布中直接编辑，并与右侧字段同步；链接、锚点、图片路径与预设、焦点、数值、布局参数和 SEO 只在右侧属性栏编辑。需要保留显式换行的标题仍使用 `textarea`，渲染器收到的值必须保持原始字符串。
- 公开页继续按路由加载实际使用的 renderer，不得为了复用 Admin 配置而把完整编辑器字段、默认值或全部组件打入公开运行时。

### 9.5 Puck 本地编辑器交互

- Admin 固定使用单一工作区：`56px` 顶栏、`256px` 左栏、可缩放画布与 `320px` 右栏。左右栏只允许折叠为 `44px`，不提供结构／编辑／预览模式、栏位换边、拖动宽度或布局预设。
- 左栏默认打开“大纲”，可切换到“添加组件”。折叠状态和当前页签只在当前客户端页面切换期间保持；刷新后恢复默认。
- 大纲显示中文名称与英文技术类型，递归展示 Slot；选择、悬停和滚动定位必须与画布双向同步。`editorDisplayName` 只属于编辑元数据，公开渲染前必须递归剥离。
- 组件目录按中文名、英文类型、用途、分类和路径别名搜索。普通浏览只显示当前 zone 允许的组件；搜索可显示不兼容结果，但不得允许错误插入。
- 进入“添加组件”时只预热一个共享预览 iframe。组件项悬停 `300ms` 或键盘聚焦后显示 `1440×900` 逻辑视口的真实效果浮层，浮层不得拦截指针或提供固定、常驻和布局设置。
- 右栏字段按“内容、媒体、链接、布局、高级”分组，“高级”默认折叠；字段使用中文主标签和英文属性键次级提示。无组件选中时显示页面设置。
- 保存状态统一为“已保存／有未保存修改／保存中／保存失败”。首次变脏后启动三分钟单次自动保存；手动保存取消当前计时，失败保持 dirty 并在三分钟后重试。
- 保存接口返回 `EDITOR_TOKEN_REQUIRED` 时，编辑器使用密码输入对话框为当前浏览器与当前站点地址设置本机 Token，并通过原保存队列立即重试。服务端不得向浏览器自动下发 `.env.local` 中的 Token，Token 不得进入页面内容、前端源码、日志或 Git。

### 9.6 ComponentLab V3 组件版式工作台

- ComponentLab 的原子编辑对象是“组件 / 版式”。Puck 继续管理正式页面文案、媒体、链接和列表内容；ComponentLab 管理共享版式与仅供 Lab 使用的样例文字；FontLab 仍是字体预设和字号档位的唯一来源。
- 工作台使用“导航 / 画布 / 属性”三栏：左栏约 `260px`，只负责分组搜索组件版式和选择内部元素；中栏占据剩余空间并承载真实 canonical renderer；右栏约 `300px`，只显示当前元素或版式整体的属性。禁止重新把导航、设备、元素和属性串成一条超长表单。
- 左栏必须把组件与版式放进同一个分组搜索选择器。界面只使用“组件与版式、可编辑元素、版式整体、桌面、平板、手机、跟随桌面、单独调整、区块高度、上下留白、元素间距、样例文字”等产品词汇，不显示作者组件、真实内容实例、结构变体、断点、节点 ID、shared 或 revision。
- ComponentLab 工具界面面向桌面和笔记本；移动端 `390×844`、平板 `820×1180`、桌面 `1440×960` 只表示画布逻辑尺寸。画布默认适配可用空间，只有外壳负责缩放和平移；iframe 不得制造独立滚动条或额外 `1px` 高度。
- 每个版式直接拥有自己的 Lab 样例。文字和按钮标签可以原地编辑并保存到 `component-design.json` 的 `sampleText`；图片来源、裁切、焦点、链接和其他正式内容不得由 Lab 修改。样例文字不得回写 `content/pages/**/*.json` 或组件默认 props。
- 所有元素格位相对 `.grid-container` 的 12 列。横向拖动保存 `start/span`；Flow 元素的纵向拖动保存顺序与 `0 / 8 / 16 / 24 / 32 / 48 / 64` 间距；Overlay 元素保存上、中、下锚点与 `8px` 步进偏移。拖动期间必须显示最终吸附结果，松手后不得二次跳动。
- 单击选择元素，双击文字进入样例文字编辑；超过 `4px` 才进入拖动，`Esc` 取消。文字框只调整栏宽并保持自然高度；普通图片调整网格宽度和 manifest 允许的展示框；全屏背景跟随版式整体高度，不提供独立缩放。
- 背景、装饰和内容图层由 manifest 固定，Lab 不允许自由改变层级。选择框不得遮挡组件内容；满屏背景只能在真实空白处或元素列表中选中，文字、按钮和普通媒体始终拥有更高命中优先级。
- `Shift` 点击支持临时多选并共同移动；组件已有语义分组可以整体选择，但不得创建或拆除永久分组。重复条目按真实 occurrence 显示选框，样例文字逐条独立，布局规则仍由同一个 role 共享。
- 可选文字或按钮为空时，Lab 必须显示不会进入公开页的虚线占位，使 manifest 声明的每个角色都有可达编辑入口；公开页面继续按真实内容决定是否渲染。
- “版式整体”可以调整区块高度档位、上下留白和整体间距，但不能在画布中拖动整个组件。字体面板只能选择 FontLab 当前存在的 preset、size、对齐和换行策略，不允许直接输入字号、字重、行高或字距。
- Desktop 是完整基础布局；Tablet 与 Mobile 显式保存 `linked/custom`。新配置默认跟随 Desktop，只有点击“单独调整”后才能编辑设备覆盖，并可“恢复跟随桌面”；恢复跟随后保留原 custom 值，便于再次启用。
- 一次完整拖动、缩放或选项修改立即自动保存；样例文字停止输入 `400ms` 或失焦后保存。请求必须串行并带 base revision、组件、版式和 operation ID，只合并目标版式后原子写入完整配置。
- 当前会话按完整操作支持撤销和重做，撤销与重做也自动保存；关闭 Lab 后历史清空，不提供跨会话历史版本。保存失败时保留本地状态并自动重试，只有仍存在未落盘修改时才在离开页面前提醒。
- revision 冲突发生在其他版式时允许重新基于最新文档合并目标 patch；当前版式也被另一窗口修改时必须保留本地结果，并明确提供“保留本地修改”与“加载最新版本”。
- `component-design.json` 版本 3 保存组件、版式、设备布局和样例文字。V2 在内存中无损迁移，旧 Tablet/Mobile 标记为 `custom`；没有真实编辑时不得只因打开 Lab 就改写文件。
- 正式页面、Puck 与 ComponentLab 必须继续引用同一个 canonical renderer 和规范化配置。Lab 的占位、文字编辑包装、选框、消息标注与临时拖动样式不得进入公开页面。
- iframe 消息必须携带协议版本、render session、递增序号、组件、版式、设备、role、occurrence 和操作阶段；组件或版式切换后，旧会话消息必须丢弃。
- 站点可视组件的视口高度使用 `--site-viewport-unit`。公开页默认值为 `1svh`；Admin iframe 与 ComponentLab 分别注入逻辑视口高度的百分之一，禁止组件直接依赖 iframe 实际 `vh/svh`。
